# 论文速读：Table-Question-Answering-for-Low-resourced-Indic-Languages

## 一句话总结
本文首次针对低资源语言引入 TableQA 任务，设计了可扩展的自动大规模数据生成与质量控制流水线，在孟加拉语（Bengali）和印地语（Hindi）上构建了两个大型 TableQA 数据集，并在孟加拉语上训练的模型超越了最强 LLM（GPT-4）。

## 研究问题与动机
- **低资源语言数据稀缺与文化事实缺失**：现有 TableQA 研究高度集中于英语等高资源语言，孟加拉语、印地语等语言几乎无标注数据和预训练模型；直接翻译英语数据集不适用于表格，因为表格是半结构化结构而非自然语句，机器翻译错误率高。
- **现有神经网络模型与低资源语言对齐差、对表格结构理解不足**：开源多语言 LLM（如 OdiaG、OpenHathi）未经表格结构训练，在结构化推理任务上表现极差；直接将英语预训练数据翻译后微调也无法捕捉本土文化事实。
- **缺乏面向低资源语言的规模化、可复用的数据生成与评估方法**：现有低资源 NLP 多为文本类任务，表格 QA 特有的数学运算、集合操作、表连接等要求全新数据构建范式。

## 核心贡献（创新点）
- **首次提出低资源语言的 TableQA 任务并实现可扩展的数据自动生成流水线**，涵盖表抽取、代码混合 SQL 生成、自然语言问题生成与答案表提取四步，适用于任何有网络存在的低资源语言。
- **设计了一种低成本、大规模的数据质量自动评估方法**：发现现成 LaBSE 模型在代码混合 SQL-NQ 对上区分能力极低（均值 0.55），因此对其微调得到 SQL2NQSim 模型，以 0.74 为阈值过滤低质量样本。
- **发布两个高质量 TableQA 数据集：BanglaTabQA（约 205 万训练样本）和 HindiTabQA（约 64 万训练样本），以及对应训练的多个开源模型**，填补了印度语言表问答领域的空白。
- **验证了训练模型的数学推理能力与零样本跨语言迁移能力**：在六种 SQL 算子类别上系统评估，并展示了孟加拉语模型在未训练的印地语测试集上的迁移效果（经后处理提升明显）。

## 方法详解
- **表格抽取**：从孟加拉语/印地语维基百科 dump 中直接提取表格，避免英语翻译的文化偏差和表格翻译错误（相比直接翻译英语 WikiTableQuestions 等数据集的优势）。
- **代码混合 SQL 生成**：使用 SQUALL 数据集中的 SQL 模板，将表格名、列名、值随机替换为低资源语言内容，生成可执行的代码混合 SQL 查询（SQL 关键字保持英文，表格内容使用当地语言）。孟加拉语生成 1,334.5 万条可执行查询。
- **自然语言问题生成（SQL2NQ）**：
  1. 首先由精通 SQL 的本语种人员对 27 个 SQL 关键字建立一对一映射，将代码混合 SQL 转化为单语 SQL-like 查询（如孟加拉语）。
  2. 用从 Spider、WikiSQL、Atis、Geoquery 翻译得到的 68,512 训练/9,996 验证样本微调 mBART-50-large 作为 SQL2NQ 模型，实现 SQL → NQ 的序列到序列生成。
- **答案表提取**：将低资源语言维基百科表格导入关系数据库，用 SQL 编译器执行生成的代码混合查询，提取答案表。
- **自动质量控制**：
  1. 丢弃无法执行的 SQL 查询。
  2. 微调 LaBSE（SQL2NQSim 模型），使用多负样本排序损失在翻译语义解析样本上训练，以 0.74 相似度阈值为分界点过滤低质量 NQ（正样本与困难负样本的分化点在 0.7 附近）。
- **测试集构建**：选取训练/验证集中未见过的表格，覆盖全部 6 种算子类别，由 3 名精通 SQL 的本语母语者手动标注，Fleiss' Kappa = 0.82，平均流利度得分 4.3/5。

## 实验与结果
- **数据集规模**：
  - BanglaTabQA：19K 维基百科表格，2,050,296 训练 / 2,053 验证 / 165 测试样本。
  - HindiTabQA：约 1,921 表格，643,434 训练 / 645 验证 / 121 测试样本。
- **评估指标**：Table Exact Match（Tab）、Row F1、Column F1、Cell F1。
- **最强结果（孟加拉语测试集）**：
  - GPT-4 基线：Tab EM = **26.83%**，Row EM = 38.67%。
  - **BnTQA-mBart 超越 GPT-4**：Tab EM = **35.88%**，Col F1 = 35.88%。
  - BnTQA-M2M：Tab EM = 28.05%。
  - BnTQA-llama（PEFT LoRA）：测试集泛化较差（Tab = 9.41%），验证集过拟合明显。
  - En2Bn（翻译基线）：仅 Row/Cell EM ≈ 4.73%，远低于本方法训练的模型。
- **印地语测试集**：HiTQA-BnTQA（用 BnTQA-mBart 初始化微调）达 Tab EM = **41.32%**，优于 HiTQA-mBart（33.06%）。
- **算子类别分析**：BnTQA-mBart 在 GroupBy 上 Tab EM = 50.00%，HiTQA-mBart 在 Sorting 上 Tab EM = 39.05%，均能泛化至未见表格。
- **零样本跨语言迁移**：BnTQA-mBart 在印地语测试集上经后处理（孟加拉数字→印地数字、SQL 关键字翻译、Google Translate 列名/值翻译）Tab = 5.74%，Row = 17.59%，Col = 5.69%，Cell = 15.49%，显著高于无后处理的 0.00%。

## 相关工作脉络
- **MultiTabQA / TaPas / TAPEx（高资源英语 TableQA）**：本文与之定位差异在于，前者专注于英语及高资源语言，且多为提取式或单表生成式方法；本文首次面向低资源语言，解决文化适配与数据稀缺问题，并提出完整的自动数据生成流水线。
- **OdiaG / OpenHathi（低资源文本 LLM）**：这些模型基于纯文本预训练，缺乏表格结构理解，本文证明在 TableQA 任务上直接应用极差（OdiaG Tab EM = 0.69%），需要专门的表格对齐训练。
- **Bhattacharjee et al. (2022)、Das & Saha (2022)（低资源翻译式数据生成）**：这些工作通过神经机器翻译将英语 QA 数据集翻译为低资源语言，但表格是半结构化非规范句子，翻译产生高错误率；本文从原始低资源维基百科直接抽取表格，从根本上避免翻译误差。
- **LaBSE / Sentence Similarity Models**：本文发现标准 LaBSE 在代码混合 SQL-NQ 对上区分能力差，因此对其微调得 SQL2NQSim，这是对已有相似性评估方法的改进与适配。
- **SQUALL 模板（Shi et al., 2020）**：本文沿用其 SQL 模板用于查询生成，但将其扩展至低资源语言代码混合场景，并构建了完整的问题生成与质量评估链路。

## 局限性与未来方向
- **依赖在线有表数据的语言**：方法仅适用于有互联网存在的低资源语言，对于 Web 存在极低的极低资源语言效果有限。
- **SQL 模板限制**：SQUALL 模板不支持多表操作和复杂查询（如嵌套子查询、join），限制了问题复杂度上限。
- **跨语言迁移后处理仍依赖翻译**：零样本迁移实验中，生成的答案表含孟加拉语内容，需借助字典和 Google Translate 后处理，翻译质量仍可能引入噪声。
- **Llama 模型在 PEFT 设置下泛化不足**：BnTQA-llama 在验证集上过拟合，测试集表现远低于编码器-解码器模型，可能与非拉丁文字的分词问题有关。

## 研究启发与可借鉴点
- **代码混合 SQL 模板生成可作为低资源结构化数据自动构建的通用范式**：将 SQL 关键字保留为英文、实体和表格内容替换为低资源语言，既保证可执行性又规避翻译误差，此思路可迁移到其他结构化数据任务（如知识库问答、信息抽取）。
- **SQL2NQSim 微调 LaBSE 用于语义相似度过滤**：针对低资源语言代码混合场景，直接用预训练相似性模型效果差，需构建正向/困难负样本对进行微调后再用于质量控制，此策略可推广至其他低资源数据筛选场景。
- **Bangla→Hindi 零样本跨语言迁移验证了表格推理能力的语言无关性**：训练数据仅含孟加拉语，模型即可在印地语上执行表推理，说明表格语义表示具有跨语言可迁移性，这一发现可为多语言统一 TableQA 模型设计提供方向。
- **六类 SQL 算子分类评估体系**：对 Arithmetic/Sorting/GroupBy/Filtering/Set/Logical 算子的分类分析，为后续研究提供了可复用的能力诊断框架，便于定位模型在特定推理类型上的短板。

## 关键术语表
**TableQA（Table Question Answering）**：从半结构化表格中回答问题并返回答案表或单元格的任务。
**低资源语言（Low-resource Language）**：缺乏大规模标注数据和预训练模型的語言，本研究聚焦孟加拉语和印地语。
**代码混合（Code-mixed）**：混合使用两种语言（如英文 SQL 关键字 + 孟加拉语表格内容）的语言现象。
**SQL2NQSim**：本文微调的 LaBSE 模型，用于评估低资源语言中 SQL 查询与自然语言问题的语义相似度。
**BanglaTabQA / HindiTabQA**：本文发布的孟加拉语和印地语大规模 TableQA 数据集，分别含约 205 万和 64 万训练样本。
**零样本跨语言迁移（Zero-shot Cross-lingual Transfer）**：在一种语言（孟加拉语）上训练的模型，无需目标语言（印地语）训练数据即可在目标语言测试集上执行任务。
**Tab/Row/Col/Cell EM F1**：本文使用的 TableQA 评估指标，分别衡量答案表的表格级、行级、列级、单元格级精确匹配 F1 分数。

## 可复现要素
- **数据集**：BanglaTabQA 和 HindiTabQA 已公开释放（论文声明）。
- **代码/模型**：数据集、训练好的模型及代码均已开源释放（论文声明链接为 [1]）。
- **关键超参**：学习率 1e-4，batch size 128（mBart/M2M）或 16（Llama，4-bit 量化），训练 5 epochs，最大序列长度 1024，单卡 A6000 48GB GPU。

- **后端模型**：mBART-50-large、m2m100_418M、Llama-7B（LoRA adapter）。
- **LaBSE 微调**：使用 Spider/WikiSQL/Atis/Geoquery 翻译样本共 68,512 训练对 + 9,996 验证对。
